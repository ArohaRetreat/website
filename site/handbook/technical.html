Application services

Firebase Hosting
Serves the website and Host Studio. Developer documentation has its own Hosting site. The public handbook runs on GitHub Pages.
Firebase Authentication
Handles Google sign-in. The booking API checks membership and the allowed action for each authenticated request.
Cloud Functions
Runs the versioned API and background workers. Website, Studio, and scoped external requests use the same booking and payment rules.
Cloud Firestore
Stores reservations, pricing policy, payments, credits, notification jobs and audit records.
Cloud Storage for Firebase
Serves optimized public media. Private guest attachments require authorized access.
Resend
Accepts queued messages and reports delivery outcomes through signed webhooks. Studio shows the recorded status.
Booking and email flow

Booking and account access

Homepage handoff
The static form carries check-in, checkout and adult count into the booking portal. The portal retains selections through Google sign-in, then asks the booking API for availability and prices.
Studio account directory
The API rechecks the verified Google session and booking-manager admin membership on each request. The pre-production directory reads approved tester accounts. Pages are bounded and responses use no-store.
CSV exports
Export checks the same access, protects spreadsheet formula cells and records the actor, request ID and row count. The export is generated on demand.
Scoped REST clients
External contract 1.5.0 includes staff reservation search and explicit early checkout. Discover the available operations with the permissions of the active integration token.

REST and MCP

Use the versioned OpenAPI contract for external clients. The local MCP server exposes typed tools over that API. Issue only the scopes the integration needs. Writes follow the same authorization, validation and concurrency rules as Studio.
