Website from pull request to live

  1. 1. Check the pull requestRun application, emulator integration, foundation and branch policy checks on the current revision. Foundation validates the documentation decision and, on main, builds the handbook and checks its links.
  2. 2. Check the merged revisionVerify CI on the current preprod or main commit. Validate the version, target, pinned assets, Hosting size budget and compatible backend before publication.
  3. 3. Deploy Hosting and verifyPublish to the branch’s Firebase Hosting site. Compare the live release, files and protected-route behavior with the expected build. Keep the deployment and live-check receipts.
Detailed deployment gates

Reporting and public updates

Delivery observer
Reads eligible GitHub runs and sanitized test results after CI completes. It sends workflow and test events and OpenTelemetry signals to Dynatrace. Verify tenant records by source run and attempt.
GitHub Pages
The workflow checks sprint dates, verified Hosting receipts, npm and live developer docs. It publishes when public content changes. Check the run’s trigger in GitHub Actions to verify whether a scheduled refresh fired.
MCP and developer docs
Each runs its own source checks. Registry metadata confirms a stable MCP publication. A validated live manifest confirms a docs deployment.
Backend changes
Functions, rules and index changes have their own release step. When required by a frontend change, verify the compatible backend first.
