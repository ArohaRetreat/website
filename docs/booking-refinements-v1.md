# Pre-production booking refinements — API0.8.0 / website0.22.0

Issue83. Preprod first; main/production remain unchanged until owner acceptance and separate promotion.

Exclusive requests use products.eventDayRate, default3000000 paise (₹30000) per selected calendar day, including both first and last days. Same-day event costs one day; continuous range ends18:00 on final day with existing accommodation agreement. Config manager validation/version guard applies. Quote/create snapshot full rate/line items; submitted new requests accept this published price and need only one host availability approval. Pending priced events hold exclusive inventory until their existing approval deadline, then release it; approval remains transactional. Existing unpriced/host-offer events retain their explicit offer/accept workflow; existing amounts never retroactively change. No payment collection, receipt or automatic confirmation.

POST /api/v1/booking/calendar is a bounded, anonymous aggregate read, throttled by caller IP (authenticated requests also allowed). Body: start YYYY-MM-DD, days1..62, kind stay/day/event, adults1..100, childrenAges0..9 (max100), optional arrival date for departure/last-day selection. Unknown fields denied. Response: settingsVersion, asOf, days[{date,available}]. Never reservation IDs, counts, contact, names, notes, room IDs or block reasons. Uses environment-specific days ledgers and overdue checked-in reservations in one read transaction, existing config blocks, exact half-open intervals and shared product policy. Arrival uses minimum one-night/one-day availability for current party; stay combines feasible private or adult-only individual allocation. Departure/last-day cells test the full anchored continuous range (max31 days), allowing11:00 checkout even when that day's arrival is blocked. Paused/full/expired/malformed dates unavailable; malformed request422, abuse429, reconciliation409. No idempotency key or writes for this read. Server availability/quote/create/approve still recheck races.

Date picker fails closed while loading/on error, supports explicit retry, suppresses stale requests after month/target/identity/dismissal changes and rechecks on every opening. Disabled days explain unavailable and cannot be selected by pointer/keyboard. Party changes invalidate displayed availability. Monitoring uses existing consent-bound dates attempted/succeeded/failed and bounded server operation without new PII.

Public-site and Living Map enquiries require current Google sign-in, including at final WhatsApp preparation. Account offers Enquire and Book separately. Enquire uses the shared existing enquiry form, preserves package/cottage hints and opens a guest-reviewed WhatsApp message only; it creates no reservation. Login cancellation does not leak form data. Account loss clears the private enquiry form and any delayed loads cannot replace a newer dialog. Account/book profile navigation remains accessible.

Resend preprod acknowledgement/host/confirmation pipeline and forced inbox remain unchanged. Production activation pending real host address, issuer address/payment instructions, production key/webhook and worker deployment; no historical replay. Full frozen stage email/PDF integration, payment ledger and feedback schedule remain issue70, not conflated with enabling a provider.

Tests: domain rate/range/hold/legacy invariance, calendar block/capacity/private-sharing/children/checkout/continuous range/privacy; DOM loading/retry/stale/keyboard/sign-in guards; actual Auth/Firestore/Storage emulator routes and permission boundaries.
